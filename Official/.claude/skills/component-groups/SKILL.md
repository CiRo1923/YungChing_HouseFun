# 共用元件的取用與歸屬

**這份只有本專案有**,規則寫在 `.tools/lint/rules-project.mjs`,整套更新時不會被覆蓋。

## 一、現成的元件能用就直接用

**寫一塊畫面之前,先看共用元件目錄有沒有做得到的。** 做得到就用它,
不要在頁面裡用 utility class 自己刻一份長得一樣的東西。

| 要做的東西 | 現成的元件 |
| --- | --- |
| 幾個項目排在一起、中間有分隔線 | `CommonMSeparator`(`--horizontal` 橫排、`--gap-x-XX` 控制間距) |
| 按鈕、連結 | `CommonMAnchor` |
| 圖片(沒有圖時自動換預設圖) | `CommonMFigure` |
| 圖示 | `CommonMSvgIcon` |

這張表只是常見的幾支,不是全部 —— 動手前把共用元件目錄底下的資料夾看過一遍。

**自己刻一份的代價在之後:** 同一種外觀有兩套寫法,改設計時只改到元件那一套,
自己刻的那幾處不會跟著變,而畫面上要並排比對才看得出不一致。

元件做不到的時候(需要的外觀或行為它沒有),**停下來問**,
不要為了一頁去改共用元件 —— 那會影響每一個用它的地方。

## 二、頻道的元件不跨頻道使用

共用元件目錄底下依頻道分資料夾:

| 資料夾 | 給誰用 | 標籤名的開頭 |
| --- | --- | --- |
| `common` | 全站 | `Common` |
| `buy` | 買屋頻道 | `Buy` |
| `member` | 會員頻道(會員中心、登入註冊那一組都算) | `Member` |

**buy 與 member 的元件不互用。** member 的頁面要用 buy 資料夾裡的元件時,
先把那支元件**搬到 `common`**,兩邊再一起用;反過來也一樣。

### 為什麼

頻道資料夾裡的元件,改的人只會看自己頻道的頁面。另一個頻道偷偷在用的話,
改了就連帶弄壞那一邊,而且要等那一頁有人打開才發現。

搬到 `common` 之後,歸屬寫在路徑上:看到 `common` 就知道全站都可能在用,
改之前會先找使用端。

### 搬的時候

搬移會改掉那支元件的標籤名(自動注入的名字跟著資料夾走,`BuyMChart` 會變成 `CommonMChart`),
原頻道的每一個使用端都要跟著改。**搬之前先說,由開發者決定**,
不要為了一頁自己動手搬。

### 哪些檔案算哪個頻道

看路徑的第一段:

| 頻道 | 包含 |
| --- | --- |
| buy | 頁面目錄的 `buy/`、共用元件目錄的 `buy/`、版面目錄的 `buy.vue` |
| member | 頁面目錄的 `member/`、共用元件目錄的 `member/`、版面目錄以 `member` 開頭的(`member.vue`、`memberAuth.vue`) |

不屬於任何頻道的(`containers/`、`common` 的元件)不檢查 —— 它們本來就給全站用。

**頁面旁的元件(`Page` 開頭的那種)不在這條的範圍**,只管共用元件目錄的頻道資料夾。

檢查:規則 `project:componentGroup`(擋)。只看畫面區段實際寫出來的標籤,
註解掉的那一段不算。

## 與相鄰規範的界線

| 規範 | 管什麼 |
| --- | --- |
| **這一份** | 要不要用現成元件、可以用哪一個頻道的元件 |
| component-conventions | 共用元件**自己的檔案**怎麼寫:載入了什麼、資料夾與檔名、對外介面 |
| tailwind-usage | 共用元件的 template 裡**寫什麼 class** |
