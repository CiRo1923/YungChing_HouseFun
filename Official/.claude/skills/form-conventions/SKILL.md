# 表單:驗證掛在哪裡

## 一、一組控制項共用一個驗證

**一題多選、一題單選的那幾個選項是「一組」** —— 它們共用同一個名字,
驗證講的也是同一件事(這一題還沒選)。

那一組**不要每一個都自己帶驗證**。做法是把驗證掛在包住整組的那支元件上
(哪一支由 `.tools/lint/project-config.mjs` 的 `FORM_GROUP_VALIDATOR` 決定,
規則的提示訊息會直接寫出實際的元件名稱)。

錯誤的寫法:

```vue
<CommonMFormRadio
  name="petType"
  v-model="apiData.HaveAnyPet"
  :rules="rules"
  :config="{ text: item.key, value: item.value }"
  v-for="(item, index) in items"
  :key="`${item.value}_${index}`"
/>
```

正確的寫法:

```vue
<!-- 整組的必填驗證掛在包裝元件,各顆 radio 只負責選取與錯誤樣式 -->
<CommonMFormHidden name="petType" v-model="apiData.HaveAnyPet" :rules="rules" v-slot="{ isError }">
  <CommonMFormRadio
    name="petType"
    v-model="apiData.HaveAnyPet"
    :config="{ text: item.key, value: item.value, isError }"
    v-for="(item, index) in items"
    :key="`${item.value}_${index}`"
  />
</CommonMFormHidden>
```

三個重點:

| 誰 | 負責什麼 |
| --- | --- |
| 包裝元件 | 掛 `rules`、顯示**唯一一則**錯誤訊息、把錯誤狀態當作 `isError` 傳下去 |
| 各個控制項 | 選取、顯示錯誤外觀(吃 `isError`)。**不帶 `rules`** |

### 為什麼

**同一句話會重複好幾行。** 每一個控制項自己帶驗證時,每一個都會各驗一次、
各產生一則訊息 —— 一題有五個選項,畫面上就會出現五行「請選擇」。

**繞過去的寫法會留下陷阱。** 常見的權宜做法是「只讓最後一個顯示、其餘用
class 藏起來」,那讓訊息的數量看起來對了,但每一個控制項其實都還在驗;
之後選項的數量變成動態的,或有人調整了順序,藏起來的那幾則就會冒出來。

**錯誤狀態要一致。** 驗證只有一份時,整組的錯誤外觀一定同時亮起、同時熄滅。
各自驗的話,理論上可能出現「這一顆紅了、那一顆沒紅」的狀態。

### 什麼情況不算一組

**名字裡帶了迴圈變數的,是各自獨立的欄位。** 例如一份表單裡有好幾位成員,
每一位都有自己的姓名欄(`name-0`、`name-1`),那幾個各自驗證是對的 ——
它們的訊息說的是不同的事(第一位沒填、第三位格式錯)。

分辨方式:**這幾個控制項是同一個問題的幾個選項,還是不同的問題?**
同一個問題就是一組,不同的問題就各自驗。

## 二、自動檢查

檢查:規則 `formGroupValidate`(擋)。判斷邏輯在 `.tools/lint/`,五個時機跑的是同一份判斷:

- **存檔時** —— 編輯器與開發伺服器會即時檢查,違規逐筆印在終端機。
- **AI 寫檔時** —— 寫檔前的 hook 比對寫入前後的內容,只擋「這次新增」的違規。
- **對話時** —— 存檔時沒修掉的違規會列進對話,直到修好為止。
- **commit 時** —— pre-commit 檢查這次提交的檔案。

本機覆核:`node .tools/lint/lint.mjs <檔案或目錄>`。

這條不自動修正。工具看得出「這一組各自帶了驗證」,看不出那個包裝元件該綁哪一個值
—— 那通常是一個合格旗標或整組的值,只有寫的人知道。

**判準不看元件叫什麼名字**,看的是「一個迴圈、一個共用的名字、每一個都自己驗」
這個形狀 —— 換一套表單元件仍然成立。專案沒有包裝元件時(設定留空)整條略過,
全專案檢查的開頭會講出來。

## 與相鄰規範的界線

| 規範 | 管什麼 |
| --- | --- |
| **這一份**(form-conventions) | 表單的**驗證**掛在哪裡、訊息顯示幾次 |
| component-conventions | 元件**自己怎麼寫**:載入了哪幾支樣式、開頭那幾行怎麼排 |
| page-conventions | 頁面**怎麼取資料**、api 資料放哪裡 |
| css-module-variables | 控制項的**尺寸級距**(內距、圓角)怎麼定義、放哪一支檔案 |

分辨方式:這次動的是驗證與訊息就看這一份;動的是元件檔案本身看元件那一份;
動的是樣式與級距看模組變數那一份。
