# 動手之前先讀一次規範

**優先順序:第 2 順位。** 低於「無法判斷就一律問」,
高於「規範自己也不能有兩份」、「修問題要治根」、「註解與文件的寫法」,
以及每一條命名與樣式規範。

低於「無法判斷就一律問」的理由:讀完規範仍然判斷不出來的情況照樣要停下來問,
讀過不等於有答案。高於其他幾條的理由:那幾條規則本身也寫在這些檔案裡 ——
沒讀就動手的話,連自己違反了哪一條都不會知道。

**開始做任何一件事之前,先把這一類的規範實際讀過一遍** ——
寫程式、改樣式、動 store、新增 api、改規範系統本身,全部適用。
不是憑印象,是打開檔案讀。

## 先同步,再讀

**這一層的規範不是在這個專案長出來的。** 整批來自元件庫那個來源,
而那邊會持續更新 —— 專案裡的那一份隨時可能已經落後。

讀了落後的版本,與憑記憶做事是同一種錯,而且**更難發現** ——
憑記憶的人知道自己在憑記憶;打開檔案讀過的人不會懷疑那一份是舊的。

**而要讀的那幾層恰好是沒有保護的那幾層。** 指紋那道(`npm run rules:verify`)
看的是 `npm run rules:files` 列出的那幾支,對不上的時候講得出是哪一支;
`.claude/` 的規範與 hooks、`.githooks/`、`.vscode/` 不在那份清單裡 ——
落後一版或被覆蓋掉,從頭到尾沒有任何訊息。

所以順序是**先同步,再讀**。同步工具是各專案自己接的(來源沒有共用的指令),
要帶哪幾支見安裝說明那一份的「需要複製的五個目錄」。

**來源專案本身沒有這一步** —— 它沒有上游。設定檔的 `SOURCE_PROJECT_NAME`
與 `PROJECT_NAMES` 對得上就是來源,規範在那裡就地長,同步的方向是從它流出去。

### 抓取要完整,不是挑幾支

**跑整批比對,不要自己挑要看哪幾支。** 哪一支變了由工具說,不由人猜 ——
憑猜的時候,漏掉的永遠是「沒想到它也會改」的那一支。

這幾種來源一律不算數:

| 不要從這裡判斷 | 為什麼 |
| --- | --- |
| 記憶 | 那是上一次讀過的版本,來源這段期間可能又改了 |
| 稍早跑過的比對結果 | 同一個理由 —— 一次同步只證明「那一刻」一致 |
| 修改時間 | 複製過來的檔案時間是複製當下,與內容新舊無關 |
| git 的 commit 差異 | 那是這個專案自己的歷史,來源的更新不在裡面 |

## 為什麼不能憑記憶

規範會被改。改過之後,記憶裡的版本就是錯的,而且錯得看不出來 ——
照著舊版本做出來的東西看起來完全正常,要到檢查工具報出來、
或是別人接手時發現兩支檔案寫法不一樣,才會知道中間有一版沒跟上。

每一輪對話開頭那份提醒只給**一句話的摘要**,那是索引,不是規範本身。
判準、例外標記怎麼寫、哪些情況不適用,全都在各自的檔案裡。
照著一句話摘要做事,等於用標題寫程式。

## 要讀哪些

**一、這一類的寫法規範(`.claude/skills/`)。**
先判斷這次要動的是哪一類 —— 樣式、元件、頁面、狀態、api、
不分檔案類別的程式寫法 —— 再讀那一類的 `SKILL.md`。
每一份的檔頭 `description` 會說它管到哪裡,對不上就換一份。

**二、跨類別的共同前提(`.claude/rules/`)。**
這一層管的是做事的方式,哪一類工作都適用:判斷不出來就問、
規範不能有兩份、修問題要治根、文字怎麼寫。

**三、會擋下來的那幾道檢查(`.claude/hooks/`)。**
寫入前的檢查會擋掉這次新增的違規。知道它擋什麼,才不會寫完整段才發現要重來。
判斷邏輯全部在檢查引擎裡,hooks 自己不做判斷 ——
所以要知道「會被擋什麼」,讀的是規則,不是 hook 的程式碼。

## 什麼時候要重讀

**同一輪對話裡改過規範之後,要重讀那一份。**
這一輪剛動過的規則,記憶裡留的是動之前的版本。

**隔了一段時間回到同一件事時,要重讀。**
中間可能有別人改過,也可能是自己在別的脈絡下改的。

**要拿某一份當依據時,當場確認它沒變。** 引用某一條去改程式碼、
或是要開發者決定什麼之前,先重新抓取那一支 —— 開頭抓過一次不算,
一件事做下來往往是幾十個步驟,而來源在這段期間會繼續更新。

代價不對稱:確認一次是一道比對;拿舊版去問的話,問的可能是一個
**來源已經修掉的問題** —— 開發者為此做了一次判斷,而那個判斷沒有對象。

同一件事也適用於回報:整理完要回報的問題之後,**送出之前重新抓一次**,
確認那幾筆還在。

## 讀完之後

讀完不等於做完判斷。規範沒涵蓋到、或套用在這個案例上有兩種讀法時,
**停下來問**,不要挑一個看起來合理的往下做 ——
那是「無法判斷就一律問」在管的事,而它的順位比這一條更高。
