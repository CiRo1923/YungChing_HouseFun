### D-14 關鍵字搜尋功能整體未完成

> 原 D-14、D-28、D-30、D-31 合併——四個子問題共享同一根因（元件尚未完成實作）

**問題1：空白狀態未顯示推薦**

- <strong>規格</strong>：未輸入任何資料時，點擊搜尋欄顯示「最近搜尋（最近 3 筆 Cookie 記錄）」＋「近 30 天最多瀏覽社區（前 3 名）」
- <strong>實際</strong>：元件設定 `minChars:1`，onFocus 不發起 suggest API 呼叫，也無讀取 Cookie 記錄邏輯；點擊空白欄位無任何彈出

**問題2：輸入時建議 API 未依規格分類**

- <strong>規格</strong>：依「社區 → 捷運 → 路段」分類顯示，最多 10 筆 + 1 筆「以輸入文字為案名搜尋」；每筆顯示 Badge（社區／捷運站／路段）與物件數量
- <strong>實際</strong>：`GET /api/v1/buy/suggest?kw=…` 無論輸入任何關鍵字，回傳恆為 <strong>1 筆</strong>，`type:"Keyword"`，無分類 Badge、無社區/捷運/路段結構（以左營、鼓山、高雄車站、捷運、社區等多組關鍵字測試，結果一致）

**問題3：選取建議項目後不觸發搜尋**

- <strong>實際</strong>：元件 `onChange` handler 僅執行 `console.log("change")` 及 `console.log(selectedItem)`，不觸發任何路由導航或搜尋 API 呼叫；使用者選取後頁面無反應，需另行手動點「搜尋」

**問題4：輸入文字後無作用於搜尋**

- <strong>實際</strong>：即使在輸入框輸入文字，不點選任何建議項目、直接按搜尋，關鍵字未傳入 API（參見 D-29）

## 八、補充說明

### URL 格式不符規格

目前測試環境 URL 格式為：

```
/buy/list/01_region?pg=1
```

規格要求為：

```
/buy/list/01_region/?pg=1
```

`/[縣市]/[地區]/[條件]/?pg=n`，請使用 `/` 結尾。

兩者格式差異大，除上述 canonical、H1、Title 問題外，URL 路徑結構本身也需對齊規格定義。請開發確認此為尚未對齊的 URL 規格，或測試環境的臨時格式。
