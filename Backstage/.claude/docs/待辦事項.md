## 地址匯入那個 tab 一點就壞(`pageApiData` 1 筆)

`pages/buy/publish/basic/_components/TabCheckAddress.vue`。

自己 `ref` 了一份送出參數,而且宣告與存取對不上:

```js
const apiData = ref({
  cityID: '', districtID: '', road: '', lane: '', alley: '',
  number: '', ofNumber: '', floor: '',        // 扁平
})

// 整支元件都這樣讀,而 caseInfo 這一層從來沒有被宣告
apiData.value.caseInfo.cityID
```

`components/buy/mTab/Check.vue` 是 `v-if="index === activeIndex"`,
所以只有切到「地址匯入」那個 tab 才會渲染 —— 平常不會發生,一點就發生。

要決定的是這份資料的性質,兩種讀法的做法相反:

| 這是什麼 | 做法 | 代價 |
| --- | --- | --- |
| 查地址用的暫存(輸入一個地址去查、把結果匯入) | 留在元件,改成不叫 apiData,並把宣告與存取對齊 | 規範那一筆要標例外 |
| 要送給 api 的參數 | 搬進 buyPublish 的 store | 那支 store 的 `apiData.caseInfo` 放的是物件本身的資料,查詢條件混進去會分不開;欄位名也對不上(這裡是 `number` / `ofNumber`,store 是 `addrNum` / `addrNumOf`) |

修之前要先知道這個 tab 原本預期怎麼運作 —— 現在的程式碼看不出來。

## api 與 store 檔名對不上 pages 第一層(`apiScope` 1 筆、`storeScope` 2 筆)

```
scripts/_api/buy/common.js   檔名 common.js 在 pages 底下沒有對應的資料夾
stores/buy/project.js        檔名 project.js 在 pages 底下沒有對應的資料夾
stores/rent/project.js       檔名 project.js 在 pages 底下沒有對應的資料夾
```

`list.js` 與 `publish.js` 已經不在清單裡 —— pages 底下有同名的資料夾,對得上。
剩下的三支是真的沒有對應頁面的那幾支。

**成因**:規則把「資源」定在檔名上,除非那一層有自己的 `.config.js` 才算服務層。
本專案的 `scripts/_api/buy/` 沒有,所以 `common` / `list` / `publish` 被拿去跟
pages 的第一層(`buy` / `demo` / `home`)比對,自然對不上。

**兩條路,都要先決定再動**:

| | 做法 | 代價 |
| --- | --- | --- |
| A | `scripts/_api/buy/` 加一支 `.config.js`,讓它成為服務層 | 本專案只有一個 baseURL,那支會是沒有實質差異的設定檔 —— 為了通過檢查而開結構 |
| B | 把 `buy/` 攤平,三支合併成 `scripts/_api/buy.js` | 檔案會很長(61 支 api),而且按功能分檔的好處沒了 |

2026-09-14 問過一次,當時的回覆是「不動層級」,所以 B 排除;A 要不要做還沒決定,
違規先留著。**不要因為想讓 lint 歸零就自行選 A** —— 姊妹專案加那支是因為後端
真的分服務(各自的網域與 token),本專案沒有那個前提。
