# 不要多起一個開發伺服器

開發人員手上本來就只會有一個開發伺服器。**這個狀況只有 AI 介入時才會出現** ——
而徵狀離成因非常遠,靠 debug 幾乎想不到。

## 會發生什麼

兩個開發伺服器同時跑,會寫同一份建置快取與暫存產物(Nuxt 是 `.nuxt/`,
兩邊都有各自的依賴快取),互相覆蓋。

開發人員看到的是:

- 存檔之後整份 CSS 不見
- `The 'p' screen does not exist in your theme` 這類「設定明明有」的錯誤
- 硬重新整理沒有用,重開瀏覽器也沒有用

而他完全不知道背後多了一個伺服器 —— 畫面上沒有任何線索指向那裡。
實際發生過一次,耗掉一個多小時。

## 要做的

**一、先確認是不是已經在跑,已經在跑就直接用那一個。**

port 寫在專案設定裡(這個專案是 `config.js` 的 `port`)。查那個 port
有沒有在 listen 就知道:

```
# Windows
netstat -ano | findstr :<port>

# macOS / Linux
lsof -i :<port>
```

有東西在 listen 就是已經在跑 —— 開瀏覽器看那個網址,不要再起一個。

**二、`EADDRINUSE` 是「已經有人在跑」,不是「舊的沒關乾淨」。**

這是最關鍵的一條。撞到 port 被佔用的時候,不要當成殘留跳過去,
**更不要換一個 port 繼續起** —— 換 port 只是讓兩個伺服器都活著,
而它們寫的是同一份產物。實際踩過的就是這一步:第一次撞到就當成殘留,
改用另一個 port,之後兩個伺服器互相踩了一個多小時。

**三、真的需要自己起的時候(開發人員沒開),要能被認出來、也要收得回來。**

- 起之前說一聲,起完把網址講出來
- 用完自己關掉,不要留著
- 不要改 port 繞過衝突

## 為什麼寫成規範而不是靠注意

這件事的成因與徵狀之間沒有任何可見的關聯:看到的是 CSS 壞掉,
而原因是背景多了一個行程。查樣式、查設定、清快取、重開編輯器都不會找到它。
規範可以在動手之前就擋掉,而 debug 不行。
