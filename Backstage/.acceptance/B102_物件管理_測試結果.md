### 3-1 規格落差（M-01～M-06）

### M-01　TAB 名稱「草稿區」與規格「未上架」不一致

- **規格**：B102 第四個狀態分類為「**未上架**」（定義：從未刊登過）。
- **實際**：列表 TAB 顯示為「**草稿區**」（路由 `/buy/list/draft`）。
- **影響**：名稱差異；功能定義一致。建議統一規格/實作用語。
- **嚴重度**：低
- 正確為：草稿區，文件未更新

### M-02　排序選項與規格不符（各 TAB 一致、未客製）

> **0804 調整：** ✅ 已修正

> **0805 複測：** ❌ 未修正 — 已成交 TAB 仍顯示預設/刊登日/到期日/留言數/瀏覽數，無「成交日」排序選項

> **0810 複測：** ✅ 已修正 — 已成交 TAB 排序列已顯示「成交日」按鈕

- **規格**：
  - 刊登中（§4.1）：預設(更新編輯時間,不可切換)、到期日、**總價**、留言數、瀏覽數
  - 已成交（§4.2）：**成交日**

- **實際**（四個 TAB 排序列皆相同）：預設、**刊登日**、到期日、留言數、瀏覽數
- **問題**：
  1.  多出「**刊登日**」（規格無）。保留
  2.  缺少「**總價**」排序（規格§4.1有）。不需要
  3.  **已成交 TAB 缺「成交日」排序**（規格§4.2要求），且仍顯示「到期日」（對成交物件無意義）。
  4.  排序列未依 TAB 客製，四個 TAB 一致。

- **嚴重度**：中

### 14.2 探索性測試缺陷

#### C-15　物件標題假連結（誤導性底線樣式）

> **0804 調整：** △ RD：確認只加底線，不加連結，保留現況（同 C-03）

> **0805 複測：** △ 維持只加底線不加連結

- **問題**：全部四個 TAB 的物件標題均使用 `<em class="underline">` 樣式，外觀與超連結相同（底線），但元素本身**無 `<a>` 包裝、無 href**，點擊後無任何反應。
- **影響**：使用者點擊標題預期進入物件詳情頁，實際無回應，造成使用者誤解與操作挫折。
- **嚴重度**：高（UX 誤導）
- **建議**：補上 `<a href="/buy/publish/basic/{id}">` 包裝，或移除底線樣式改為純文字顯示。

#### C-16　批次按鈕零選取時靜默無反應

> **0804 調整：** ✅ 已修正

> **0805 複測：** △ 視覺確認

- **問題**：未勾選任何物件的情況下，直接點擊「續刊」或「下架」批次按鈕，介面無任何回饋（無 toast、無 alert、按鈕外觀無變化），使用者不知道需先選取物件。
- **嚴重度**：中（UX 回饋缺失）
- **建議**：顯示 toast 提示「請先勾選物件」，或在 0 選取時將批次按鈕設為 disabled 並加上 tooltip 說明。

#### C-17　非數字 pg 參數導致 HouseFun Error 系統錯誤頁

> **0804 調整：** ✅ 已修正

> **0805 複測：** △ 視覺確認

- **問題**：手動修改 URL `?pg=abc`（任何非數字值），頁面呈現系統錯誤頁（HouseFun Error）而非優雅降級。<br>對比：`pg=999`（超出範圍）→ 空白態；`pg=0` / `pg=-1`（無效數字）→ 自動視為第 1 頁。
- **技術根因**：Nuxt 路由或後端 API 對非數字 pg 值未做 `parseInt()` / NaN 防護。
- **嚴重度**：中（URL 篡改可觸發，一般使用者不易遇到）
- **建議**：在路由 middleware 或 API 層對 `pg` 參數執行 `parseInt()` 並 fallback 至 1；或以 Nuxt `definePageMeta` 驗證 query params。

#### C-18　搜尋欄 Enter 鍵無效

> **0804 調整：** ✅ 已修正

> **0805 複測：** △ 視覺確認

- **問題**：在關鍵字搜尋輸入框輸入文字後按 Enter，不觸發搜尋；需手動點擊「搜尋」按鈕。
- **影響**：鍵盤為主操作者（含輔助技術使用者）無法用 Enter 觸發搜尋，不符合業界通用 UX 預期。
- **嚴重度**：中
- **建議**：在 `<input>` 監聽 `@keydown.enter` 事件並呼叫搜尋方法。

#### C-19　鍵盤無障礙缺陷（Escape / Space）

> **0804 調整：** △ RD：無相關規格，不列入修正

> **0805 複測：** △ 維持不修正（無相關規格）

> 回覆：暫不影響功能，可以之後再處理

- **問題**：
  1.  Escape 鍵：已開啟的篩選下拉選單不關閉。
  2.  Space 鍵：checkbox 上按 Space 不切換勾選狀態（自訂 `sr-only` 樣式覆蓋原生鍵盤行為）。
- **影響**：無法以純鍵盤操作篩選功能，不符合 WCAG 2.1 鍵盤可存取性基本要求（SC 2.1.1）。
- **嚴重度**：中（無障礙）

- **問題**：當進行刊登續刊時，黃金曝光會一起跟著續刊，到期日會一起增加

#### N-05　自動刷新次數未把刊登贈送的算進去

- **問題**：物件卡片上的自動刷新(N)，N並沒有算到贈送的3次

#### N-06　自動刷新到期時，未從設定介面中消失

#### N-07　自動刷新套用範本時，沒有套用到免費贈送的設定

- **問題**：使用套用自動刷新範本時，會全部都直接設定成新增次數，贈送的免費3次，並沒有套用到，導致出現免費次數跟範本有重覆的時間出現
- **建議**：例如使用8次的範本，範本前3個應該是套用在免費贈送的3次，後5個才會是新增或是修改剩餘的5次（當扣除免費3次，剩餘不足5次時才會是扣額度新增)

#### N-08　已下架的仍在刊登期內核取方塊位置異常且無作用

- **問題**：已下架的仍在刊登期內的check box位置跑到篩選器列上，且點擊並無作用
- **建議**：請參考設計稿，應在篩選器列下方；點擊應該會篩選仍在刊登期內的物件（不會顯示已到期或無法刊登的物件）

#### N-09　已下架刊登到期日排序，資料排序異常

- **問題**：不論是升幂或降幂，列表並沒有依下架日期排序
- **建議**：使用物件的下架日期排序

#### N-10　已到期物件未下架

- **建議**：物件ID：5772780、6590541、6639101

#### N-11　快期物件，刊登到期日未變色提示

- **問題**：物件5417990，刊登到期日小於10天，日期文字未變色
- **建議**：當距離**刊登到期日少於 10 天（< 10 天）時，系統便會出現提示訊息，並變更樣式（變色變紅提示）**來提醒經紀人

#### N-12　管理頁上架中的物件案名，未加上C端頁面連結

- **問題**：上架中的物件案名沒有C端頁面連結
- **建議**：上架中的物件，點擊案名會另開該頁在C端的物件明細頁

#### N-13　留言管理，狀態文字顏色異常

- **問題**：留言管理的狀態文字，已回覆未回覆顏色沒有統一，有些是紅有些是灰；更換狀態後會維持現有的顏色，並沒有變跟狀態改變
- **建議**：未回覆-紅色；已回覆-灰色

#### N-14　留言管理，選擇多筆無法更改狀態

- **問題**：使用留言前的Check box勾選多筆留言，無法進行更改狀態；要點擊全選才能點擊批次更改狀態
- **建議**：協助確認是否異常

#### N-15　全選留言更改狀態後，全選未取消

- **問題**：留言管理使用全選，進行狀態變更後，Check Box已取消勾選，但仍顯示已選9筆，且能再次更換狀態
- **建議**：批次設定狀態後，應清空已選的物件

#### N-16　手動新增並直接刊登的物件，列表上未顯示地址

- **問題**：使用新增刊登物件，並直接選額度上架的物件，在列表沒有顯示地址
- **建議**：物件：6639122

#### N-17　手動新增物件，存入草稿後，在草稿區狀態會顯示【資料不完整，請先編輯資料】

- **問題**：手動新增物件並選擇存成草稿，必填都有填，但在草稿區會顯示資料不完整，無法直接點擊刊登上架
- **建議**：必填欄位都有資料時(正常情況下都應該會有)，狀態會是編輯儲存，沒有資料不完整的提示，此狀態下刊登按鈕必須是可以點擊，然後選擇額度的

#### N-18　瀏覽物件頁時，瀏覽數會計算成2次

- **問題**：每次刷新頁面時，會計算2次瀏覽數
- **建議**：刷新頁面時，只算1次，請協助確認；同時發現，瀏覽數是即時更新，因此瀏覽數的燈箱，上方的 每日 00:00 更新數據 文案請協助移除
- **調整**：請協助將瀏覽數燈箱的列表排序改為遞減，日期新的在前面

#### N-19　編輯物件資料時，車位資料都會被清空

- **問題**：編輯物件時車位資料都會被清空；如：車位類型、車位數量、車位管理費....
- **建議**：應保留資料

#### N-20　新增照片時，新增的照片會取代掉封面照

- **問題**：新上傳照片時，會變成放在第一張，取代掉原本的封面照
- **建議**：照片依上傳時間遞增排序，新上傳的放在後面，不能影響到前面上傳的順序，使用者自行拖拉可以改變順序

#### N-21　拖拉照片順序沒作用

- **問題**：編輯物件照片，拖拉照片時順序無作用；更改封面照片時，編輯頁會改變，但列表及C端照片不會改變
- **建議**：需依編輯頁的照片順序顯示在C端

#### N-22　編輯物件資料時，會自動全選照片

- **問題**：編輯物件時，會先自動把照片全選，此時若取消勾選按送出，會變成將照片刪掉
- **建議**：編輯時不需全選照片，多選照片是為了刪除照片方便；但未選照片時送出編輯，會將照片刪掉請協助確認異常行為

- **問題**：設定成交時，日期若選當下日期，會出現 400 錯誤訊息 /api/v1/buy/realEstate/deal 400 錯誤: One or more validation errors occurred.

- **問題**：留言管理，新的留言會被放到最後，不利於經紀人查看

- **問題**：屋齡輸入完工日期時，屋齡不會顯示
