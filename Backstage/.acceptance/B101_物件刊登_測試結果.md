### EF-01　CKEditor 特色描述欄 Stored XSS（高危）

> <strong>0804 調整：</strong> ✅ 已修正

> <strong>0805 複測：</strong> ✅ 已修正 — CKEditor setData/getData 已正確過濾 XSS（script/img onerror/javascript: CSS 均剝除）

- <strong>問題</strong>：「特色描述」富文字編輯器（CKEditor 4，instance: `editor1`）對惡意 HTML 注入<strong>完全不過濾</strong>。以下 payload 均可注入並被 `editor.getData()` 原封傳回：

  | Payload                                           | getData() 結果                              | 風險                       |
  | ------------------------------------------------- | ------------------------------------------- | -------------------------- |
  | `<script>alert("XSS")</script>`                   | <strong>完整保留</strong> ❌                | 任意 JS 執行               |
  | `<img src="x" onerror="alert(1)">`                | <strong>完整保留</strong>（onerror 存在）❌ | 事件處理 JS 執行           |
  | `<p style="background:url(javascript:alert(1))">` | <strong>完整保留</strong> ❌                | CSS 注入執行 JS            |
  | `<iframe src="https://evil.com">`                 | 加入 `sandbox=""` 後保留 ⚠️                 | 部分緩解，但 iframe 未移除 |

- <strong>影響範圍</strong>：若 CKEditor HTML 直接儲存至資料庫並帶至 C 端物件頁，任何瀏覽該物件的買家都會在其瀏覽器中執行惡意 JS。
- <strong>嚴重度</strong>：🔴 <strong>嚴重（Critical）</strong> — Stored XSS，影響所有 C 端訪客
- <strong>建議</strong>：
  1.  後端儲存前必須伺服端 HTML Sanitization，不可僅依賴前端。
  2.  前端設定 CKEditor `config.allowedContent` 白名單，或用 DOMPurify 過濾 `editor.getData()` 結果。
  3.  僅允許安全標籤：`p/br/strong/em/ul/li/ol/h2/h3`。

## 七、PM複驗新回報

<br>

### N-01　點擊調整地圖定位，會鎖住地址的顯示至路段名

- 點擊地址欄位的「調整地圖定位」，然後關閉 → 這時地址下方的顯示至路段名會被鎖定，不論怎麼改地址都不會變 
- <strong>建議</strong>：顯示名要跟著地址隨時變動

### N-02　聯絡資訊自行輸入修改後，再選同會員資訊時不會更新回會員資訊

- 點擊自行輸入，並且更改資料或是刪除，再點擊同會員資訊時，這時資料會是自行輸入的內容(或是被清空) 
- <strong>建議</strong>：每次點同會員資料時，都應該用會員資料覆蓋過去

### N-03　必填欄位未填寫，儲存草稿未阻檔

- 當必填欄位未填寫時，可以進行儲存草稿
- <strong>建議</strong>：必填沒有資料時，需要阻檔儲存草稿；不然會出現空的物件資料

### N-04　點擊取消會卡住

- 刊登頁點擊取消會卡住
- <strong>建議</strong>：取消後，導到物件管理列表頁
